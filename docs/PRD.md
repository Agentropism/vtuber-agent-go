
# 本项目 产品需求文档（PRD）

## 项目概述

本项目 是一个面向 Bilibili 直播的 AI VTuber 实时交互系统，由三个子系统协作：
- **Open-LLM-VTuber**：Agent 服务端，负责 LLM 对话、TTS 语音合成、Live2D 驱动
- **onebot-gateway**：Go WebSocket 网关，接收多平台事件并分发
- **bilibili-live**：Rust B站直播协议客户端，接收弹幕/SC等事件

> 以下需求按实现复杂度从低到高排序。

---

## 一、自动重连机制
- **复杂度**：低
- **现状**：agent 服务端重启后，网关和 bilibili-live 无法自动重新连接，需手动重启
- **需求**：各组件在服务端重启时具备自动重连能力，无需人工干预

## 二、B站事件类型补全
- **复杂度**：低
- **现状**：SC（Super Chat）、点赞等事件无法正确反序列化（报 missing field 错误）
- **需求**：补全事件结构体字段，支持所有B站开放平台事件类型

## 三、UI 界面重载
- **复杂度**：低
- **现状**：前端页面/资源加载存在刷新问题
- **需求**：后端重启时自动刷新前端页面而非只能手动刷新

## 四、音频播放排序与动作优先级调度
- **复杂度**：低~中
- **现状**：多句回复的音频片段播放顺序错乱/重叠；SC 感谢、待机动画、LLM 回复之间无优先级区分
- **需求**：
  - 对 TTS 输出做排序，确保按句子顺序依次播放，不重叠
  - 引入动作优先级机制：SC 感谢/系统事件不可被打断，LLM 主动互动可被高优先级打断，待机动画随时可打断
  - 高优先级事件到来时，低优先级动作暂停或排队，完成后恢复

## 五、表情映射
- **复杂度**：低~中
- **现状**：LLM 输出的表情标签没有正确对应，表情标签被当作字符展示
- **需求**：表情标签正确解析并映射到 Live2D 表情，不在文本中显示原始标签

## 六、语速自然度与情感音色
- **复杂度**：中
- **现状**：当前合成语速单一，听感不自然，所有情绪用同一语速/音调输出
- **需求**：
  - TTS 输出需根据 LLM 回复的情绪标签动态调整语速、音调、音量等参数
  - 不同情绪（开心、悲伤、愤怒、兴奋、低语等）对应不同的语音表现
  - 调整语速参数或更换更自然的 TTS 模型，支持语速/语调变化

## 七、自动找话题
- **复杂度**：中
- **现状**：直播间无弹幕时 VUP 沉默
- **需求**：加入空闲时自动发起话题的机制（如定时主动说话、根据上下文/热点生成话题）

## 八、消息分级处理与 Skill 化调用
- **复杂度**：中~高
- **现状**：所有消息无差别进入 LLM 对话流，QQ 消息处理逻辑与直播弹幕耦合，职责不清晰
- **需求**：
  - 引入三级消息处理机制：
    - **L1 快速匹配**：简单关键词/指令（如打招呼、点歌）直接响应，绕过 LLM，零延迟
    - **L2 LLM 决策**：标准对话流程，含记忆注入和上下文裁剪
    - **L3 人工介入**：敏感内容/高优先级事件触发通知，等待主播或房管决策
  - QQ 的能力以 Skill（Tool Calling）形式按需调用，而非始终参与对话流
  - 区分主播两种状态：
    - **直播中**：QQ 消息低优先级处理，不中断直播对话流；仅响应特定指令（如切换配置、查询状态）
    - **下播/未开播**：QQ 作为主要交互入口，正常响应群聊/私聊消息
  - Skill 注册机制：QQ 相关能力（群管理、点歌、查询等）注册为独立 Skill，由 Agent 根据上下文和主播状态决定是否调用

## 九、SC 高权重记忆与 Tool Calling
- **复杂度**：高
- **现状**：当前无记忆模块，SC 与普通弹幕同等对待；LLM 无法主动查询记忆或触发行为
- **需求**：
  - 建设记忆模块，SC 事件赋予更高权重，优先进入长期记忆并在对话中被优先召回
  - 事件权重层级：SC > 普通弹幕 > 点赞/进入直播间等通知类事件
  - LLM 具备 Tool Calling 能力，可自主决定何时调用以下工具：
    - 检索记忆（查询与当前观众/话题相关的历史记忆）
    - 触发 Live2D 动作/表情（由 LLM 判断当前语境该用什么表情）
    - 发送 SC/礼物感谢（自动触发感谢行为）
    - 查询观众信息（获取观众画像用于个性化互动）

## 十、VUP 模块重构
- **复杂度**：极高
- **现状**：当前 VUP 模块（Live2D 驱动、表情映射、动作控制、前端渲染）耦合严重，扩展性差，表现力不足
- **需求**：VUP 整个模块需要重构，将 Live2D 驱动、表情系统、动作系统、口型同步解耦为独立可替换组件，为后续接入更高质量的渲染方案（如 3D 模型、自研渲染引擎）留出接口
- **子项**：
  - 自训练模型：基于直播场景语料训练/微调专属模型，特化优化人设一致性、口语化表达、弹幕互动节奏，降低对 prompt 工程的依赖
  - 模型动作与口型：丰富动作库，实现口型同步，表情过渡自然流畅
  - 动作数据驱动：录入动作数据，让 AI 识别数据并识别最优方案保存到资料库，实现动态驱动
