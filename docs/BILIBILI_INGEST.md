# B 站接入：上报端要求与已知坑

网关**不含 B 站协议实现**：它只在 `/bilibili` 上收事件（`[[clients]]` 里 `platform = "bilibili"`、
`adapter_key = "bilibili_live"`）。连开放平台、鉴权、心跳、重连、拆帧全部由**外部上报端**负责，
凭据也在上报端自己的配置里。

> 本仓库此前内置过一个 Go 版开放平台客户端（`internal/core/gateway/bilibili`，2026-09 删除）。
> 下方「已知坑」是那次实现相对原 Rust 客户端（`bilibili-live`）修正过的**实测缺陷**——
> 如果上报端选原 Rust 客户端，这些坑会原样回来。

## 上报端必须做到

1. **事件信封原样转发**：`{"cmd": ..., "data": ...}` 不要重编码字段；网关侧按
   `gateway/event/bilibililive` 认字段（宽容化解析，未知 cmd 透传为空 Action）。
2. **身份规则**：优先 `open_id` 字符串，缺失时才用 uid；上传时写入 `platformEvent`。
3. **覆盖 11 类 cmd**：弹幕、礼物、SC、SC 撤回、大航海、点赞、进入直播间、开播、下播、互动结束、弹幕镜像。
4. **断线必须真重连**，并让「进程活着但连接已死」可观测。
5. **退出时调 end 接口**结束互动会话，否则同一 `id_code` 的下次启动会被平台拒绝。

## 已知坑（原 Rust 客户端的实证缺陷）

| 缺陷 | 后果 | 验收要点 |
| --- | --- | --- |
| 压缩帧（`version=2`）解压后只读 `body`、忽略 `body_muti` | 压缩帧里的**所有事件被静默丢弃** | 造一个 v2 压缩帧，确认子包逐个派发 |
| 重连循环不可达（内部任务永不返回） | 实测断连后 **27 分钟零次重连** | 断开服务端，确认退避重连并恢复收事件 |
| 帧长只校验上限、不校验是否超过已收字节 | 越界 **panic** | 构造畸形帧头，确认返回错误而非崩溃 |
| 鉴权失败只记日志、不断开连接 | 以未鉴权状态**永久空转** | 用错凭据启动，确认上抛错误并进重连 |
| 选路用 ICMP ping，任一条地址不通即整体启动失败 | 单点不可达就**起不来** | 屏蔽其中一条地址，确认仍能启动 |

## 验证上报

本仓库没有自动化冒烟：验证上报端时用任意 WebSocket 客户端，按 [`EVENT_CONTRACT.md`](EVENT_CONTRACT.md)
的信封格式把事件打到 `/bilibili`，然后看日志与前端是否按预期响应——不经过真实上报端，也不需要真实凭据。
